## 1. 引言：JIT编译的挑战与机遇

历史上，快速JIT编译（Just-In-Time compilation）被视为一项黑魔法。要编写一个快速的JIT编译器，你需要精通汇编语言。一个典型的例子是：目前没有任何生产级数据库拥有自己的JIT编译器，它们要么使用LLVM，要么生成C/C++代码。这两种方案都存在编译时间过长的问题，限制了其适用性。如今，借助AI，通过直接针对汇编语言编写JIT编译器，实现快速编译变得前所未有的简单。这也是新数据库超越旧数据库的一个机会领域。在构建pgrust时，我最初认为实现JIT编译器会非常困难。最终，在AI的辅助下，我发现它比预期的要容易得多，这也成为了pgrust性能卓越的部分原因。pgrust的JIT编译器在约5微秒内完成代码编译，这使我们能够对每条SQL查询进行JIT编译，而不仅仅是其中的一部分。在这篇文章中，我将带你了解如何构建自己的快速JIT编译器。我们将以一个使用JIT编译的简单正则表达式引擎为例。

## 2. 为什么需要JIT编译

JIT编译是指在运行时（即“即时”）生成编译代码的实践。如果做得好，它可以带来巨大的性能提升，通常是2-5倍，有时甚至更多。JIT编译的主要应用场景是当你在运行时获得的信息会显著改变程序行为时。这在编程语言解释器中尤为常见，因为它们接收要执行的代码是在运行时。JIT编译器在编程语言之外的领域也很有用，例如数据解析。有时，直到运行时你才知道要解析的数据的模式（schema），JIT可以帮助解决这个问题。让我们先实现一个玩具正则表达式引擎。为了简单起见，我们只支持两个特性：字面量字符串和重复（即正则表达式中的*）。我们还将跳过解析器，直接将正则表达式表示为已解析的Rust结构。这意味着我们将能够支持诸如“apples”和“b(an)*”这样的字符串，但不支持交替（alternation）或后顾（lookbehind）等。在代码中，这非常简单。我们将有三种节点类型：字面量字符串节点、重复节点和连接节点（即两个节点的组合）。代码如下：enum Node &#123; Literal( 'static str), Concatenation(Box&lt;Node&gt;, Box&lt;Node&gt;), Repetition(Box&lt;Node&gt;) &#125; fn literal(text: 'static str) -&gt; Node &#123; Node::Literal(text) &#125; fn concatenation(left: Node, right: Node) -&gt; Node &#123; Node::Concatenation(Box::new(left), Box::new(right)) &#125; fn repetition(body: Node) -&gt; Node &#123; Node::Repetition(Box::new(body)) &#125;

## 3. 解释器实现与性能瓶颈

为我们的正则表达式引擎编写解释器也很直接：fn match_node(node: Node, input: [u8], pos: usize, next: dyn Fn(usize) -&gt; bool) -&gt; bool &#123; match node &#123; Node::Literal(text) =&gt; &#123; let literal = text.as_bytes(); input[pos..].starts_with(literal) && next(pos + literal.len()) &#125; Node::Concatenation(left, right) =&gt; &#123; match_node(left, input, pos, |left_end| &#123; match_node(right, input, left_end, next) &#125;) &#125; Node::Repetition(body) =&gt; &#123; match_node(body, input, pos, |body_end| &#123; match_node(node, input, body_end, next) &#125;) || next(pos) &#125; &#125; &#125; fn interp_match(regex: Node, input: str) -&gt; bool &#123; let bytes = input.as_bytes(); match_node(regex, bytes, 0, |pos| pos == bytes.len()) &#125; 这个正则表达式引擎非常简单，代码不到20行，但让我们看看它的性能表现。为了对比，我们将代码与针对该正则表达式专门实现的手写代码进行比较。我们的示例使用正则表达式“b(an)*”。手写代码看起来像这样：fn handwritten_b_an_star(input: str) -&gt; bool &#123; let bytes = input.as_bytes(); let mut pos = 0; if pos == bytes.len() || bytes[pos] != b'b' &#123; return false; &#125; pos += 1; while pos &lt; bytes.len() &#123; if bytes[pos] != b'a' &#123; return false; &#125; pos += 1; if pos == bytes.len() || bytes[pos] != b'n' &#123; return false; &#125; pos += 1; &#125; true &#125; （有方法可以优化这段代码并使其更快，但为了我们的目的，它作为一个很好的比较基准。）当我针对这两个实现进行基准测试时，手写版本比解释器快10-20倍。显然，还有很大的改进空间。现在，让我们看看如何使用JIT编译来获得一个性能与手写版本相当的正则表达式引擎。

## 4. JIT编译的步骤与设计决策

JIT编译代码有两个步骤。首先，为要运行的代码生成汇编。一旦有了代码，就将汇编代码打包成一个函数，你可以像调用程序中的任何其他代码一样调用它。为了生成汇编，我们将使用一种称为“复制并修补”（copy-and-patch）的方法的变体。其思想是，我们有一系列针对要JIT编译的不同操作的汇编模板。这些模板被称为“模板”（stencils）。当我们想要JIT编译一个操作时，我们取出相关的模板，并根据操作的具体情况做小的调整。这与填充真实的模板非常相似。通过将几个填充好的模板串在一起，我们可以在运行时构建一个与手写版本性能相似的程序。我们将采取以下路径：首先，我们查看为“b(an)*”生成的ARM64代码。然后，我们将重复的指令序列转换为可重用的模板，编写一个发射器（emitter），从正则表达式AST填充和组合这些模板，最后将生成的指令复制到可执行内存中，以便Rust可以像普通函数一样调用它们。为了让你了解这是如何工作的，最容易的是从生成的代码开始，然后回溯到JIT编译器本身。再次强调，我们处理的是正则表达式“b(an)*”。为了布局一些设计决策：我们将使用一个栈进行回溯。栈将跟踪如果正则表达式遇到死胡同我们应该去的状态。我们匹配的字符串将以空字节结尾。这意味着，如果我们到达字符串末尾，任何字符比较都会自动失败。这意味着我们不需要在任何点进行长度比较。对于程序的状态，我们将使用以下寄存器：x0 – 当前字符串位置和返回值；x1 – 用于回溯的栈顶；x2 – 用于回溯的栈底（这用于确定栈是否为空）；x9 – 用作临时变量。对于程序的输入，我们将传递：x0 – 指向字符串开头的指针；x1 – 指向我们将用作栈的位置的指针。

## 5. 生成的ARM64代码详解

现在我们已经处理了这些，让我们逐部分讲解生成的汇编。这特别针对macOS上的ARM64。首先，我们有初始化程序的序言（prologue）。它所做的只是通过将栈顶和栈底设置为传入的值来初始化栈：0: aa0103e2 mov x2, x1 接下来，我们有检查字符“b”的代码。如果它看到一个不是“b”的字符，我们跳转到一个处理回退逻辑的代码块。否则，我们推进字符串中的位置：; CHAR 'b' 4: 39400009 ldrb w9, [x0] ; 加载当前输入字节 8: 7101893f cmp w9, #0x62 ; 是'b'吗？ c: 54000281 b.ne 0x5c ; 否 - 回退块 10: 91000400 add x0, x0, #1 ; 是 - 推进输入 接下来，我们有重复部分“(an)*”。对于重复，我们需要进行回溯。如果我们在这里回溯，那意味着我们立即跳转到循环的末尾。这意味着我们需要将循环后的指令地址和我们在字符串中的位置都存储在栈上。14: d2800989 movz x9, #0x004c ; 构建恢复地址 18: f2a00009 movk x9, #0x0000, lsl #16 ; = 0x1_0000_004c 1c: f2c00029 movk x9, #0x0001, lsl #32 ; (循环出口) 20: f2e00009 movk x9, #0x0000, lsl #48 ; 24: a8810029 stp x9, x0, [x1], #16 ; 将(exit, pos)压入栈 有了这些，我们现在可以执行重复的主体。这将检查字符'a'和'n'，如果看到它们，就回到重复的顶部，但使用新的字符串位置。; CHAR 'a' 28: 39400009 ldrb w9, [x0] 2c: 7101853f cmp w9, #0x61 ; 'a'? 30: 54000161 b.ne 0x5c ; 否 - 回退块 34: 91000400 add x0, x0, #1 ; CHAR 'n' 38: 39400009 ldrb w9, [x0] 3c: 7101b93f cmp w9, #0x6e ; 'n'? 40: 540000e1 b.ne 0x5c ; 否 - 回退块 44: 91000400 add x0, x0, #1 ; JMP 48: 17fffff3 b 0x14 ; 回到循环顶部 现在我们过了循环。这是回溯时跳转的地方。一旦我们完成重复，我们就到了正则表达式的末尾。我们现在要做的就是检查是否在字符串的末尾。如果在字符串末尾，我们返回1表示成功。如果不是，那意味着正则表达式匹配失败，我们需要运行失败逻辑来进行回退。4c: 39400009 ldrb w9, [x0] 50: 35000069 cbnz w9, 0x5c ; 不在NUL - 回退块 54: d2800020 mov x0, #1 ; 成功 58: d65f03c0 ret 最后，我们有回退逻辑。这检查栈是否为空。如果为空，我们返回0。如果不为空，我们从栈中弹出回退地址和回退字符串位置，然后跳转到回退地址。5c: eb02003f cmp x1, x2 ; 还有帧吗？ 60: 54000060 b.eq 0x6c ; 否 - 放弃 64: a9ff0029 ldp x9, x0, [x1, #-16]! ; 弹出(resume, pos) 68: d61f0120 br x9 ; 跳转到那里 6c: d2800000 mov x0, #0 ; 不匹配 70: d65f03c0 ret

## 6. 构建模板（Stencils）

既然你已经看到了编译后的代码，你应该开始理解复制并修补编译器是如何工作的。我们有共同的指令集，它们之间只有微小的差异。对于这些功能块中的每一个，我们可以编写一个函数来生成相应的代码。每个函数将接受用于修改代码的值。例如，stencil_char的参数之一将是正则表达式中要比较的字符。我们将直接将该字符插入机器代码中。序言很简单，因为它只是一个代码块：const PROLOGUE_WORDS: usize = 1; fn stencil_prologue() -&gt; [u32; PROLOGUE_WORDS] &#123; [0xAA0103E2] // mov x2, x1 &#125; 对于字符比较，我们需要插入我们正在比较的字符以及跳转到回退逻辑的位置：const CHAR_WORDS: usize = 4; fn stencil_char(byte: u8, stencil_pos: usize, fail_pos: usize) -&gt; [u32; CHAR_WORDS] &#123; [ 0x39400009, // ldrb w9, [x0] 0x7100013F | ((byte as u32) &lt;&lt; 10), // cmp w9, #byte 0x54000001 | cond_branch_offset(stencil_pos + 2, fail_pos), // b.ne fail 0x91000400, // add x0, x0, #1 ] &#125; 对于重复，我们有循环开始处压栈的代码和跳转到末尾的代码：const SPLIT_WORDS: usize = 5; fn stencil_split(resume_addr: u64) -&gt; [u32; SPLIT_WORDS] &#123; [ 0xD2800009 | addr_bits(resume_addr, 0), // movz x9, #addr[0..16] 0xF2A00009 | addr_bits(resume_addr, 1), // movk x9, #addr[16..32], lsl 16 0xF2C00009 | addr_bits(resume_addr, 2), // movk x9, #addr[32..48], lsl 32 0xF2E00009 | addr_bits(resume_addr, 3), // movk x9, #addr[48..64], lsl 48 0xA8810029, // stp x9, x0, [x1], #16 ] &#125; const JMP_WORDS: usize = 1; fn stencil_jmp(stencil_pos: usize, target_pos: usize) -&gt; [u32; JMP_WORDS] &#123; [0x14000000 | branch_offset(stencil_pos, target_pos)] // b target &#125; 然后我们有匹配和失败块，它们相当简洁：const MATCH_WORDS: usize = 4; fn stencil_match(stencil_pos: usize, fail_pos: usize) -&gt; [u32; MATCH_WORDS] &#123; [ 0x39400009, // ldrb w9, [x0] 0x35000009 | cond_branch_offset(stencil_pos + 1, fail_pos), // cbnz w9, fail 0xD2800020, // mov x0, #1 0xD65F03C0, // ret ] &#125; const FAIL_WORDS: usize = 6; fn stencil_fail() -&gt; [u32; FAIL_WORDS] &#123; [ 0xEB02003F, // cmp x1, x2 0x54000060, // b.eq +3 (到下面的mov) 0xA9FF0029, // ldp x9, x0, [x1, #-16]! 0xD61F0120, // br x9 0xD2800000, // mov x0, #0 0xD65F03C0, // ret ] &#125; 为了完整起见，这里是我们使用的辅助函数，它们帮助我们向指令中插入特定数据：// 计算条件分支（b.ne / cbnz）的分支偏移字段： // 从分支到目标的指令数，存储在位5..24。 fn cond_branch_offset(branch_pos: usize, target_pos: usize) -&gt; u32 &#123; let instr_count = target_pos as i64 - branch_pos as i64; // 可能为负 (((instr_count as u64) & 0x7FFFF) &lt;&lt; 5) as u32 &#125; // 计算无条件分支（b）的分支偏移字段： // 同样的想法，但存储在位0..26。 fn branch_offset(branch_pos: usize, target_pos: usize) -&gt; u32 &#123; let instr_count = target_pos as i64 - branch_pos as i64; // 可能为负 ((instr_count as u64) & 0x3FF_FFFF) as u32 &#125; // 提取绝对地址的16位，为movz/movk立即数定位。 fn addr_bits(addr: u64, part: usize) -&gt; u32 &#123; (((addr &gt;&gt; (16 * part)) & 0xFFFF) as u32) &lt;&lt; 5 &#125;
