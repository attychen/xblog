# AI聊天太费钱？新方法让多智能体对话省一半token

> 原文：[https://arxiv.org/abs/2606.05304](https://arxiv.org/abs/2606.05304)

## 1. 多智能体聊天，怎么就成了烧钱大户？

想象一下，你让一群AI助手一起写代码、做研究，它们之间会怎么交流？目前的主流做法是让它们自由对话——就像一群人在群里聊天，想到什么说什么。但问题来了：据原文，这种无约束的自然语言通信会迅速膨胀token用量，吞噬共享上下文窗口，最终既拖慢系统性能，又推高推理成本。你可能会想，不就是多聊几句吗？可在大语言模型的世界里，每个token都是真金白银。而且，当多个智能体轮番发言，上下文窗口很快就被无关紧要的闲聊填满，真正有用的信息反而被淹没。这篇来自arXiv的论文（arXiv:2606.05304）就瞄准了这个痛点：多智能体系统（MAS）的通信效率，已经成了制约其规模化应用的关键瓶颈。

## 2. 五种通信策略大比拼：没有万能药，但有核心规律

研究团队分析了五种常见的智能体间通信策略，并在两种典型的多智能体拓扑结构（比如链式、星型）上做了测试。结果发现，没有一种固定策略是普遍最优的——这就像你不能用同一种沟通方式对待所有同事，有的需要详细报告，有的只要关键结论。但有趣的是，所有高效策略都有一个共同点：它们都保留了下游智能体所需的“动作中心信息”。换句话说，智能体之间传递的，不应该是完整的思考过程或冗余的背景，而是“我做了什么”和“当前状态是什么”。这个发现看似简单，却直击要害：很多MAS设计者只顾着让智能体“说人话”，却忘了它们真正需要的是可执行、可理解的行动摘要。

## 3. PACT协议：把聊天变成状态更新，省token又提效

基于上述规律，论文提出了PACT（Protocolized Action-state Communication and Transmission）协议。它的核心思路很巧妙：把智能体间的通信看作一个“公共状态更新”问题。每个智能体在输出原始内容后，不是直接丢进共享历史，而是先压缩成一个紧凑的“动作-状态记录”。这就像开会时，每个人发言前先写一张便签：“我完成了A任务，当前系统状态是B”。据原文，PACT在不同MAS拓扑上都能显著改善性能-成本权衡——用更少的token实现同等甚至更强的任务表现。更令人兴奋的是，它在真实编码工具上效果拔群：让OpenHands的解决率提升，同时每个解决任务节省10%的token；对SWE-agent则能保持解决率不变，但输入token减半。这可不是实验室里的花架子，而是实打实的降本增效。

## 4. 总结：少说废话，多干实事——AI协作的未来方向

PACT的启示其实超越了技术本身。它告诉我们，在多智能体系统中，沟通不是越自然越好，而是越精准越好。就像人类团队协作需要“会议纪要”和“行动项”，AI之间也需要结构化的信息传递。未来，随着多智能体系统在软件开发、科学研究、自动化运维等领域大规模落地，通信效率将直接决定系统的经济可行性。PACT提供了一个优雅的解决方案：不改变底层模型，只优化信息传递方式，就能省下大量成本。如果你正在搭建自己的多智能体应用，不妨去他们的GitHub仓库看看代码（论文已开源），说不定能帮你省下一大笔API账单。毕竟，在AI的世界里，少说废话，就是真金白银。
