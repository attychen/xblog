# AI Agent聊天太啰嗦？PACT协议让多智能体系统省一半Token

> 原文：[https://arxiv.org/abs/2606.05304](https://arxiv.org/abs/2606.05304)

## 1. 为什么多智能体系统需要管住嘴？

想象一下，你让几个AI助手一起帮你写代码。它们互相发消息，但每个都说一堆废话：'我刚刚思考了一下，觉得这个问题很有意思，让我先回顾一下历史……' 是不是很抓狂？这就是当前多智能体系统（MAS）的普遍困境。据原文，这类系统通常只规定角色、流程和轮次，但智能体之间传递的内容往往是'无约束的自然语言'。结果呢？Token用量飞速膨胀，共享上下文窗口被塞满，系统性能下降，推理成本飙升。说白了，AI们聊嗨了，但你的钱包在哭泣。这个问题有多严重？原文提到，在两种常见的MAS拓扑结构下，他们分析了五种通信策略，发现没有一种固定策略是万能的——但所有高效消息都有一个共同点：保留下游智能体所需的'动作中心信息'。这就像开会时，你只需要知道'谁做了什么、下一步要干啥'，而不是听对方从早餐吃啥开始讲起。

## 2. PACT协议：让AI学会说重点

基于这个洞察，研究者们提出了PACT（Protocolized Action-state Communication and Transmission），翻译过来就是'协议化动作状态通信与传输'。它的核心思想很简单：把智能体之间的通信当成一个'公共状态更新问题'。每个智能体的原始输出，在进入共享历史之前，都会被压缩成一个紧凑的'动作状态记录'。这就像你发微信前先自己写个摘要：'已执行A，得到结果B，建议下一步C'。据原文，PACT在不同MAS拓扑结构下，一致地改善了性能-成本权衡——用更少的Token实现了相当或更强的任务表现。具体数据很惊艳：在OpenHands编码框架中，PACT将每个已解决问题消耗的Token降低了10%；在SWE-agent上，输入Token直接砍半，而任务解决率不受影响。这可不是小打小闹的优化，而是实打实的效率革命。

## 3. 从论文到实践：PACT如何改变AI协作？

PACT的价值不仅在于省Token，更在于它重新定义了AI协作的底层逻辑。过去，我们总想让AI更'像人'——自由聊天、表达情感。但事实证明，在任务导向的多智能体系统中，这种'人性化'反而是累赘。PACT告诉我们：AI之间最好的沟通，是像计算机协议一样精确、简洁。这有点像从'写信'进化到'发电报'——每个字都要有价值。据原文，PACT的代码已公开在GitHub上，这意味着开发者可以立即在自己的项目中尝试。想象一下，如果你在开发一个由多个AI Agent协作的客服系统或代码审查工具，PACT能让你用一半的Token成本达到同样的效果。对于创业公司来说，这可能是降低成本、提升竞争力的关键武器。

## 4. 总结：少说话，多做事——AI协作的未来

PACT的启示远远超出技术层面。它让我们反思：在AI系统设计中，'效率'和'智能'并不矛盾，但需要重新定义'智能'的含义。一个聪明的AI Agent，不是话最多的那个，而是能用最少信息完成任务的。据原文，研究者们分析了五种通信策略，最终发现'动作状态通信'是最优解——这本质上是一种'最小必要信息原则'。未来，随着多智能体系统在编程、客服、自动驾驶等领域的普及，PACT这类协议可能会成为标准配置。毕竟，当AI们学会'少说话、多做事'，我们人类才能真正享受到技术带来的红利。
