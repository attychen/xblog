## 2. 四大组件：Build 2026的技术拼图

Build 2026的四项技术共同完成了这个演示。每一项本身都很有趣，组合在一起就构成了这个演示。

**wslc容器API**
wslc是Windows的新Linux容器运行时。我单独写过相关文章，但简而言之，它能在Windows中原生运行OCI容器，提供CLI和API。这个应用直接使用API：创建会话、加载镜像、创建带端口映射的容器并启动它。wslc尚未集成到WSL中，但几周后就会通过wsl.exe --update --pre-release进入稳定版前的WSL。不过代码已经在开源的WSL中，所以如果你想提前使用，可以从主分支构建。风险自负。

**WinUI Reactor，无需XAML**
该应用是一个Microsoft UI Reactor应用。Reactor是一种新的代码优先方式来构建WinUI 3界面：你用C#编写UI作为可组合函数和状态钩子（hooks），就像在React中一样，而不是编写XAML和代码隐藏文件。这个项目中没有单个.xaml文件。谢天谢地。整个界面在App.cs中使用Reactor工厂构建：标题栏、启动页面和桌面表面，通过状态切换。启动屏幕和嵌入式桌面都是Reactor元素。

**Azure Linux 4.0**
Azure Linux 4.0是基础镜像。它是微软的Linux发行版，4.0版本基于Fedora Linux 43的快照构建。这个细节对这个项目很重要，因为Azure Linux没有附带桌面或GUI包。它是一个通用服务器和容器发行版。但由于底层是Fedora 43快照，你可以指向Fedora 43仓库并从那里拉取XFCE，而且……大部分能工作。这是一个糟糕的hack，我不会在任何正式项目中使用，但它很好地说明了共享包血统能带来什么。再次感谢开源。

**.NET 10**
该应用面向.NET 10和WinUI 3，通过Windows App SDK打包。dotnet run启动它时带有包标识，ReadyToRun预编译以加快冷启动速度，单个publish命令即可生成x64或ARM64构建。整个项目是一个.slnx文件，用dotnet build构建。

## 3. 工作原理：从启动到桌面的流畅流程

流程很短。应用打开后显示一个带有Azure Linux标志和旋转动画的启动屏幕。在后台，它确保桌面镜像存在（首次运行时构建），然后请求wslc启动容器。容器在XRDP服务器后端运行XFCE。应用通过回环地址连接到该服务器，将Windows RDP客户端停靠在窗口上，当会话显示在屏幕上时，它卸载启动页面。窗口变成了桌面。RDP客户端自动登录并填充标题栏下方的所有区域。从外部看，这个应用就像一个Linux桌面。没有可见的容器、没有可见的RDP提示、没有可见的管道。0:00 / 0:22 1×

## 4. 巧妙hack：组件间的非完美整合

有趣的部分在于这些组件无法完美契合的地方。以下是我最喜欢的一些。

**启动旋转动画是真正的合成，而非GIF**
加载页面上的Windows风格启动圆圈由六个围绕中心旋转的点组成，它们像真实操作系统启动旋转动画一样聚拢和散开。它由原始合成视觉元素构建：每个点都是一个精灵形状，其偏移量运行一个循环的Vector3关键帧动画，该动画从缓动扫描中采样，每个点在时间上延迟以形成拖尾效果。它在挂载时启动，在合成器上无限循环，每帧不运行任何托管代码。

**在WinUI下托管RDP控件**
桌面表面是Windows RDP客户端ActiveX控件mstscax.dll。真的。让它能在WinUI窗口内绘制……费了不少功夫。当控件被重新父级化到WinUI DesktopChildSiteBridge下时，其DirectX呈现器从不绘制；如果创建时隐藏或重新样式化为分层窗口，控件会直接崩溃。因此，它根本不在WinUI树内部。它存在于一个由主窗口拥有的无边框WinForms窗口中，在准备就绪前停靠在屏幕外，然后通过一个跟踪计时器粘贴到占位矩形上，该计时器跟随窗口移动和调整大小。Reactor绘制窗口和启动UI，拥有的窗体承载RDP表面，计时器保持它们对齐。这并不优雅，但能工作。

**时间同步**
容器时钟已通过Hyper-V时间同步跟踪主机。启动器将主机的Windows时区ID转换为其IANA名称，并在容器启动时重新指向/etc/localtime，这样桌面时钟与主机匹配，而无需触碰时钟本身。

## 5. 构建要点：从容器镜像中获得的实用经验

以下是从构建容器镜像中获得的一些来之不易的经验。在假设它们仍然有效之前，请先验证。

**在构建时栅格化SVG图标**
Fedora 43移除了librsvg gdk-pixbuf加载器。SVG解码现在通过glycin进行，它使用bubblewrap进行沙盒化，而bubblewrap无法在容器内创建用户命名空间。结果是每个SVG图标都渲染为缺失占位符。解决方法是在镜像构建期间将每个主题SVG栅格化为PNG，并保留bubblewrap安装，以便任何遗留调用静默失败。

**通过RDP的音频需要编译模块**
容器会话是独立的虚拟机，因此没有WSLg音频可借用。可行的路径是pipewire-module-xrdp，在构建阶段针对镜像自身的PipeWire编译，然后在pipewire-pulse启动后按顺序启动。

**怀旧元素**
为了怀旧，XFCE桌面使用了Bluecurve主题的复刻版，这是Red Hat在2002年发布的样式。懂的自然懂。镜像还安装了Visual Studio Code和PowerShell，因为桌面需要编辑器和shell。毕竟这是Azure Linux。

## 6. 构建指南：如何自己动手

仓库中有完整步骤，但大致如下：克隆包含子模块，运行设置脚本获取先决条件（.NET 10 SDK、Visual Studio组件、CMake），然后从捆绑源码构建并安装WSL，以便提前获得wslc。构建Azure Linux XRDP镜像，在应用项目中将EnableWslcSdk设置为true，然后执行dotnet build和dotnet run。从主分支构建WSL会用新构建替换已安装的WSL。你可能不应该在需要WSL保持绝对稳定的机器上这样做。这是一次性的。目的是将微软在Build 2026上展示的组件组合起来，看看将它们连接在一起会发生什么。一个Linux桌面，在窗口中，来自容器，运行在Windows上，且看不到任何XAML。再次感谢开源。
